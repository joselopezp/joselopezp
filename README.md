## 🧭 How I Work

Every project follows **CRISP-DM** as the structural backbone — because it forces the right question first: *what business decision does this support?*

**Lean** eliminates waste at every phase:
- No exhaustive EDA — only what informs the decision
- No over-engineered models — simplest model that solves the problem
- No technical-only output — every project ends with a business-readable conclusion

Before automating anything, I run the **five-step order**: question the requirement → delete the step → optimize → accelerate → automate. Most "automation" requests disappear at step two.

The analytical chain always runs:

```
Business Problem → Decision to Support → Data → Model → Business Impact
```

## 🛒 Shipped Product — TuttyCosas Kids

**[tuttycosaskids.com](https://tuttycosaskids.com)** · Live DTC ecommerce · Chile 🇨🇱

Not a portfolio project — a real store taking real payments. Architecture, code, copywriting, analytics and logistics, built and operated solo.

| Layer | What I built |
|---|---|
| Frontend | Vanilla JS / HTML5 / CSS3 · modular · mobile-first · no framework, no build step |
| Backend | TypeScript on serverless edge · KV datastore · object storage + CDN for assets |
| Payments | MercadoPago · HMAC-SHA256 signed webhooks · server-side price recalculation |
| Analytics | GA4 · GTM · Clarity · Meta Pixel + Conversions API — full funnel instrumented |
| Growth | Abandoned-cart recovery, transactional email, social proof from live data only |
| Security | JWT admin auth · rate limiting · bot protection · zero client-trusted pricing |
| CI/CD | Push-to-production pipeline, ~28s build, typecheck gate before every commit |

**Engineering decisions I can defend in an interview:**

- Prices are **never** trusted from the client — every checkout recalculates server-side from the datastore
- One source of truth for the catalog; the static seed exists only to avoid an empty-state flash on first paint
- A non-technical collaborator edits the full catalog with zero CLI and zero deploys
- Every bug that took 2+ diagnostic attempts is documented with a traceable code, so it never gets re-debugged
- No paid marketing until funnel and UX quality scores clear a defined threshold — measured, not guessed
